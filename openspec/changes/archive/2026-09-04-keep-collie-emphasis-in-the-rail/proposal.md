## Why

The rail's row was just given Collie's card, and it was given it to EVERY row. Collie's own list
does not do that, and the file that draws it says why in as many words: card chrome on 100% of rows
is wallpaper rather than emphasis — a Working row and a Recent row drawn identically throw away the
four-level priority `triage()` has just finished computing. The dashboard reserves the card for the
sections that mean a person is wanted here and draws the rest as flat rows in one bordered group, so
the SHAPE carries the signal: see a card, something wants you; all flat, nothing does.

The rail lists the same objects in the same order, and the operator read the difference immediately —
Ready · unseen stands out on the dashboard and did not stand out here.

## What Changes

- The rail draws a row as a card in the sections Collie's own set names, and as a flat row in one
  bordered group everywhere else.
- That set is READ from the dashboard rather than copied, so which sections mean "a person is wanted
  here" stays one rule with one definition.
- A flat row picks up the rest of Collie's flat treatment with it: no radius, the hover on the row,
  the blocked left rail, and a resting state ring filled with the ground it actually sits on.

Non-goals:

- Any change to triage, to the sections themselves, to favourites, to the row's reading order, or to
  which corner its control and its age sit in.
- Any change to Collie's own Agent list or card beyond exporting the set it already had.

## Capabilities

None.

### Modified Capabilities
